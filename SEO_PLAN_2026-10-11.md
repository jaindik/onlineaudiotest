### 5. Fix the top-bar language control (45–75 minutes)

The present problem is visible in code: English is the actual default locale, but the top bar hides the language control on English pages. Implement a **real, server-rendered language selector** in `src/layouts/Layout.astro` today if the time allows:

1. Show a labeled `Language` control on every page, including English pages. English should be the first option and shown as the current selection on root English routes.
2. Build options from the canonical locale registry in `src/lib/i18n.ts`, with human-readable language names. Do not derive display labels from URL slugs.
3. On a page with a matching alternate URL, each option should link directly to that page’s equivalent. If a translation is not available for that route, link to that locale’s home page or omit the option for that specific page; never construct a URL that returns 404.
4. Make the control keyboard accessible: a visible label, focus state, current-language indication, and predictable keyboard selection. Use native links/select semantics and make it work without JavaScript.
5. Keep English root URLs and existing localized URLs unchanged. Keep `lang`/`dir`, canonical, and reciprocal `hreflang` correct for each route. Google’s guidance asks for a consistent set of alternate links on every version and identifies `x-default` as a fallback for unmatched languages. [Localized versions guidance](https://developers.google.com/search/docs/specialty/international/localized-versions)
6. Do not auto-redirect users or crawlers based only on browser language. Let the user choose. If an explicit choice is remembered, store it only after the user selects a language, and do not override a directly requested localized URL.

8. Check desktop/mobile layouts and one route each for English, `pt-BR`, and a prefixed locale such as `de-DE`. Verify the selector’s equivalent URLs, page language, canonical, and alternates in the generated HTML.

**Acceptance criteria:** English pages visibly show English as selected/default; a localized page can return to the equivalent English page; every option lands on a valid equivalent or an intentional locale home fallback; keyboard and no-JavaScript navigation work; no route, canonical, or locale metadata changes unexpectedly.

If the selector is too large to implement and inspect carefully tonight, write the selected route-resolution approach and create a narrowly scoped follow-up for tomorrow. Do not replace it with client-only URL rewriting.

## Measurement cadence and stop rules

- **Daily for 7 days:** record complete-day clicks and impressions, deploy incidents, and index/serving errors. Use a rolling 7-day view only as an alert, not as a causal conclusion.
- **Weekly:** compare the latest complete 28 days with the previous 28 days by page/query, then segment the material losses by country and device. Use the same property, search type, and filters each time.
- **After snippet edits:** evaluate page + query CTR with position and impressions side by side. Avoid declaring a win from very small samples or a position change.
- **After technical fixes:** verify status, canonical, robots, rendered content, and sitemap immediately; inspect GSC indexing/performance over subsequent days.
- **Stop and investigate:** if a release coincides with broad deindexing, a sudden status/redirect failure, or a sustained loss in both GSC clicks and GA4 organic sessions. Roll back only when the release is credibly tied to the regression and rollback restores the expected behavior.
